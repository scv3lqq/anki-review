## Credential design (before implementation)
Store the entire file-based ChatGPT auth.json snapshot as an opaque string inside the existing encrypted Secrets payload, not a permanent access token. Preserve envelope version 1 and existing claude_token and anki_key fields. Add grader_provider and codex_auth with omitempty. Missing saved provider means claude. GRADER_PROVIDER chooses the initial setup default; a saved choice wins thereafter.
The owner performs codex login --device-auth using an isolated temporary CODEX_HOME and imports auth.json through a file input in setup/settings over the existing authenticated connection. Never expose credentials back through any API. The application does not implement OAuth itself: the supported CLI refreshes auth.json. Serialize Codex calls, reread the credentials after every invocation including failure/cancellation, and commit changes before returning results. A failed credential persistence fails grading closed.
On successful vault Seal/Open retain the derived encryption key and envelope metadata in memory, never the password. Reseal refreshed Secrets with the current key, same KDF metadata, fresh nonce and atomic file replacement. Password changes replace this handle. A restart loses the handle and credentials and stays locked until owner login. Logout retains the existing server-unlocked behavior.
Owner SaveCodexAuth(previous,next string) serializes via pwMu then mu, verifies unlocked and previous snapshot equality, merges only Codex credentials into current Secrets, reseals with current handle, increments settings version. Concurrent password changes use the newest handle; stale settings changes return ErrChanged. Do not perform refresh synchronously inside OnUnlock (owner.mu is held).
Temporary CLI credentials exist only for a call in a private 0700 home with 0600 auth file; delete afterward. Deployment uses memory-backed RuntimeDirectory via /run and TMPDIR; no persistent sessions or diagnostic logs. CLI must have no execution tools, MCP, hooks, inherited instructions/config or inherited auth env. Version mismatch fails closed before receiving cards.

## Shared definitions

Keep rubric/template bytes unchanged. Retain claude.Prompt wrapper for compatibility. Reject duplicate requested card results, missing requested results and invalid requested grades; continue ignoring unknown extras and accepting domain.ParseGrade variants. Clip feedback at 2000 runes as before.
- codex.Grader fields Bin, Model, Dir string; Timeout time.Duration; Auth func() string; SaveAuth func(previous,next string) error. Grade implements review.Grader. Check(ctx context.Context, auth string) (string,error) returns the updated snapshot, without SaveAuth. No raw CLI diagnostics in errors. Stable safe classifications for authentication, usage limit, timeout, cancellation, invalid output and unsupported version. Bound stdout/stderr and structured result files, do not truncate and accept oversized valid prefixes.
- domain.Secrets adds GraderProvider string and CodexAuth string. config.Config adds GraderProvider (default claude), CodexBin (default codex), CodexModel. Validate provider strictly claude|codex. Existing Claude variables unchanged.
- owner.Checker uses CheckGrader(ctx context.Context, provider, credential string) (string,error), plus existing CheckAnki. owner.Options adds DefaultProvider string. SetupInput adds GraderProvider,CodexAuth string; UpdateInput adds GraderProvider,CodexAuth *string. Status adds GraderProvider and GraderConnected (safe boolean, no credential). Provider error field grader_provider; Codex credential error field codex_auth. Claude field/message compatibility preserved.
- vault.Vault adds Reseal(s domain.Secrets) error using retained handle. owner.Vault includes Reseal; update test doubles. Owner SaveCodexAuth(previous,next string) error as above. Avoid lock inversion and mutable aliasing.
- app grader becomes review.Grader backed by provider router reading owner.Secrets per call, Claude and Codex adapters remain independent. Checker returns candidate refreshed auth; route selected on next grading call after settings save. HTTP setup/settings accept grader_provider and codex_auth; session includes safe provider/status. Existing clients omitting new fields continue to work.
- UI provider selects in setup/settings, Claude token shown for Claude, auth.json file input for Codex; never prefill credentials. Status explicitly distinguishes selected provider and connection availability; checking/saving supplies progress and actionable reauthentication failures.

## Pre-implementation dry-run corrections
- Check refresh must not be discarded on optimistic settings conflict: app checker detects when the candidate snapshot equals current saved CodexAuth, calls codex.Check, and commits any returned changed snapshot through SaveCodexAuth even if Check returns an error. Owner Update may then return ErrChanged and require retry; refreshed credentials are durable regardless of a concurrent password-only update. For newly imported credentials, return updated candidate to owner and seal it with settings/setup; never overwrite unrelated newer imported credentials. Deterministic test: saved OAuth A, Check rotates A to B, concurrent password-only change seals A under new password, refresh merges B under latest key, stale settings returns ErrChanged; restart with new password opens B. Grader.Check must return refreshed auth alongside an execution error.
- Deployment must install both supported provider binaries so settings selection works without root; smoke both selected configured provider and availability of the alternative. GRADER_PROVIDER selects initial setup default and does not expose or override encrypted saved provider. Pin/check both installers independently; retain CLAUDE_VERSION behavior. Explicit CODEX_BIN/CLAUDE_BIN paths require executable validation and are not silently replaced.
- Runtime directory must be proven memory-backed on Linux before writing Codex auth: use /dev/shm private temp directories or verify configured TMPDIR via statfs TMPFS_MAGIC (service TMPDIR=/run/anki-review is tmpfs). Fail safely if not memory-backed. macOS temporary auth is removed after use, document local filesystem/encryption boundary. RuntimeDirectoryMode=0700, no relaxing systemd restrictions.
- Auth import validates bounded JSON shape (tokens.access_token, tokens.refresh_token, tokens.id_token and account_id as required by supported CLI); reject empty or API-key-only credentials with actionable codex_auth field error. Validation errors never quote source bytes. Imported session must be dedicated to this service; CLI refresh owns rotation.
